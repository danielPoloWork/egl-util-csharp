# 2026-06-30 — Milestone 5: in-memory eventing & messaging

## Done

- Application abstractions: `IEventBroker` (async `PublishAsync<TEvent>`) and `IEventHandler<TEvent>`.
- Infrastructure: `EventBroker : BackgroundService, IEventBroker` on a bounded `System.Threading.Channels`
  channel — single consumer, per-event DI scope, runtime-type dispatch via a cached compiled delegate,
  back-pressure, graceful best-effort drain on shutdown (ADR-0007).
- 58 tests pass (4 new): single-delivery, **concurrent exactly-once delivery from 8 publishers × 500
  events**, null-guard, and handler-failure isolation. build `-warnaserror`, test, format,
  `--locked-mode` all green. Adopted patterns: Producer-Consumer, Publish-Subscribe.

## Adversarial review (caught and fixed before the PR)

- **HIGH:** an unhandled handler exception faulted the single consumer permanently → all further events
  silently dropped. Fixed: per-handler isolation (logged + continue) + a last-resort per-event guard.
- A cancelled `stoppingToken` was passed to handlers during drain → token-aware handlers short-circuited
  and queued events were effectively lost. Fixed: handlers get `CancellationToken.None` (run-to-completion).
- `MethodInfo.Invoke` wrapped sync handler throws in `TargetInvocationException`. Fixed: cached compiled
  delegate (direct `HandleAsync` call).
- `PublishAsync` racing shutdown leaked `ChannelClosedException`. Fixed: translated to
  `InvalidOperationException` + documented.
- Documented runtime-type dispatch + the best-effort/ShutdownTimeout drain caveat; trimmed
  Infrastructure detail out of the Application-layer XML docs; added optional `ILogger` observability.
